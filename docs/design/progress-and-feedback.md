# 进度、通知与稳定玻璃界面

状态：设计与实现契约，尚未实现界面或完成浏览器验收。遵循根目录 `AGENTS.md` 的业务语义与 `../architecture/data-and-network.md` 的传输预算，所有 AI 输入仅为论文标题。

## 1. 四阶段反馈

用户始终能知道当前在做什么、完成多少、剩余工作为何等待，以及是否需要自己处理。

| 阶段 | 展示与计数口径 | 完成条件 |
| --- | --- | --- |
| 期刊信息获取 | 搜索/预览处原位显示“正在查询期刊资料”；多本验证显示已完成本数 / 固定目标本数；单请求总量未知时用文字状态 | 本地目录查询或 Crossref 验证返回真实结果；资料缺失可作为明确结果，服务不可用须单列失败 |
| 论文抓取 | 已完整完成期刊数 / 本轮目标期刊数；当前期刊显示已获取记录、已完成日期分片和分页状态；新增、重复、失败分开计数 | 所有有效 ISSN 与日期查询路径分页结束，页面及 checkpoint 已提交；空结果也必须查完才能完成 |
| AI 过滤 | 对本轮需要过滤的唯一论文标题显示已完成 / 需处理数，同时列出保留、排除、不确定、失败/等待数 | 所有适用项都有当前配置下有效且已持久化的结果；不确定按保留；未启用过滤明确显示“不需要过滤” |
| 中文标题翻译 | 对需要翻译的标题显示已完成 / 需处理数，并区分缓存命中、待配置、重试与失败 | 所有适用项已有当前版本的有效译题；过滤排除且无收藏翻译需求、已归档且无处理需求的记录不算翻译积压 |

- 期刊资料已内置时直接展示，不人为延迟或播放假进度。预览未完成前不把操作标记成已关注；关注写入和后台抓取状态分别反馈。
- 四阶段可以并行推进不同期刊；阶段顺序约束落实到每篇论文，不用全局锁等待所有期刊抓完才显示已经完成的译题。
- 计数来自唯一业务记录及有效结果，不按 HTTP 请求次数、重复页或重试次数累加成功数。命中有效缓存也算完成，另列缓存数量；一次外部调用不是一篇论文的完成单位。
- 本轮窗口与目标快照固定。取消关注的目标显示“已取消”并单列数量，不能假装抓取成功；新关注的独立任务不偷偷扩大旧任务分母。全部取消且没有成功期刊时不得标记实例初始同步成功。
- AI 候选总量随抓取和过滤逐步发现。在上游枚举结束前，分母标记为“已发现，仍在增加”，不将临时 `完成数 = 已发现数` 宣称为最终 100%。各阶段保存 `totalKnown`/枚举结束标志；无适用项显示“不需要处理”，有完整查询且结果为空显示“完成，0 篇”。

## 2. 完成度与失败状态

- 已封闭且准确的总量才能使用确定百分比：`有效完成数 / 本轮适用总数`。期刊抓取可以显示本轮“已完成期刊占比”，同时说明它不等于论文数量或耗时占比。不能把 Crossref 各 ISSN/日期查询的 `total-results` 相加当作去重论文总数。
- 总量未知时显示已完成数量和当前工作，例如“已抓取 428 条，正在读取下一页”；不设置 `aria-valuenow`，不显示虚构的 90% 或倒计时。未知进度采用静态轨道加状态文字，无需循环扫光或水波。
- 不设置固定的 25%/25%/25%/25% 总进度，也不根据时间匀速增长。首版汇总使用阶段标签与真实计数，不生成无法解释的整体百分比或 ETA。
- 过滤尚未结束时翻译显示当前已发现任务的进度；待适用集合封闭、全部有效结果提交后才能标记该阶段完成。后续新论文、新配置重处理使用独立任务/版本，不能让已经完成的同一任务倒退或悄悄重开。
- 状态至少区分排队、执行、等待重试、等待配置、成功、部分失败、失败、取消和不适用。失败项不计入成功分子；存在失败时显示“已结束，部分失败”和重试入口，不能以绿色 100% 代替成功结论。
- 没有 AI 凭据时显示“论文已同步；翻译等待配置”，未开启过滤显示“不需要过滤”；基础同步可以单独成功，全流程不能假称 AI 已完成。配置错误、额度不足、429 等显示可操作原因和可确认的下次重试时间，不泄漏 key 或内部堆栈。
- 进度以数据库提交为准，web 与 worker 重启后仍能读取同一任务 ID、版本、计数、checkpoint 和失败原因。客户端收到较旧版本不回写 UI；轮询断开显示“连接中断，最后确认于…”，保留最后可信数值，后台是否继续依实际心跳判断。
- 状态接口维持单个有界摘要和已有 15 秒活动轮询；不为了动画提高请求频率。界面说明进度为最近确认值。用户发起操作立即原位反馈，之后用响应和轮询更新。
- 运行中任务的进度入口一直保留，换页后紧凑入口仍可发现，刷新后恢复。可以折叠明细，不可把折叠当作停止任务。成功后显示完成态至少 3 秒再淡出活动进度；失败、等待配置和部分失败不得定时消失，保留到解决或用户明确确认，确认后仍可在任务详情查阅。

## 3. 归档、收藏与通知时间

| 操作 | 服务端确认后的通知 | 时间与交互 |
| --- | --- | --- |
| 期刊整刊归档 | “已归档《期刊名》的 N 篇论文”，标明包括未加载、AI 隐藏及已收藏项；收藏仍可访问 | 至少 8 秒，附撤销按钮；撤销期限以服务端返回时间为准，不按客户端时间推断 |
| 撤销归档 | “已恢复本次归档的 N 篇论文” | 完整可见至少 3 秒后渐隐；不恢复更早已归档项 |
| 收藏 / 取消收藏 | “已收藏” / “已取消收藏”，必要时附截断标题；取消收藏不代表恢复收件箱 | 完整可见至少 3 秒后渐隐 |
| 写入失败 | “收藏未保存”或“归档失败”，附可操作原因与重试入口 | 至少 3 秒；需用户处理的错误保留至确认，原位错误不随通知消失 |

- “完整可见至少 3 秒”从通知进入完成且页面可见时开始计算，之后才用 **200ms opacity** 渐隐；入场 150ms opacity，均使用 `cubic-bezier(0.23, 1, 0.32, 1)`。阅读时间与渐隐动画时间分开配置。
- 悬停、键盘焦点在通知内或页面不可见时暂停阅读计时；离开后继续剩余时长。通知排队期间不扣时，不能在用户首次看到前过期。用户可以主动关闭结果通知，关闭不撤销操作。
- 归档撤销期限默认至少 8 秒，服务端明确返回 `undoExpiresAt`。悬停/隐藏暂停通知计时不自动延长服务端撤销期限；恢复页面时重新校验，已过期按钮说明期限已过，不提供无效撤销承诺。
- 请求发出先显示“正在保存/归档”，乐观更新可立即反馈按钮状态，但成功通知只在持久化确认后出现。响应丢失时用同一个操作 token 重试/查询结果；确认前显示“结果待确认”，不能擅自宣称失败或成功。
- 同一操作 token 的重试、状态轮询与重载不重复通知。连续多次操作可将尚未展示的同类结果合并为明确数量；已展示通知发生合并时重新保障新内容至少 3 秒阅读时间，归档撤销 token 不可被错误合并。
- 大规模归档若必须异步执行，复用真实任务进度并在完成后显示结果通知，不用“请求已接收”冒充归档完成。
- 通知是即时反馈，最终状态以数据库、按钮、期刊数量和收藏页为准；用户无需依赖一条已经消失的通知判断是否保存。

## 4. 布局与玻璃稳定性

- 任务区使用页面布局预留的紧凑状态槽，汇总一条当前任务状态；阶段详情只在用户展开后占正常文档流，不自动拉开侧栏/抽屉、不盖全屏、不抢焦点、不推走阅读位置。多任务只显示汇总，详情分页查询。
- 桌面结果通知最多两条，单条宽度不超过 360px，并安排在布局预留边缘区域；空间不足切换为单条。手机只显示一条，在导航上方预留内容不被覆盖的通知槽，遵守 `env(safe-area-inset-bottom)`。不能用大量 toast 堆高或透明外壳掩饰实际遮挡。
- 通过任务缩略状态、短通知与按需详情控制面积；长刊名/标题省略并提供可访问完整名称，长错误移到展开详情。放不下时转为可滚动的正常流详情，不扩大浮层占满屏幕。通知外的区域不拦截点击/滚动，通知不抢输入焦点。
- 背景环境光静止；玻璃外壳保持克制无色 tint 与边缘高光，子行透明，不叠卡片。高频进度、通知、计数与重复列表使用 CSS 磨砂，不创建折射 canvas，也不采用“液体填充”、波浪、弹簧、呼吸、视差或跟随指针的动态形变。
- 少量稳定顶栏/侧栏可逐步增强边缘折射，保持 `warp: false`。尺寸/视口确实变化时节流约 180ms，贴图按尺寸/圆角/视口/配置共享并释放；普通进度更新不触发 rebake，不用不断变化的 React key 重挂组件。Safari/Firefox 保留可读的磨砂降级。
- 玻璃壳与内容动画分开：不在折射表面或其祖先上动画 transform/filter/blur/radius，不插入时间变化的噪声位移；动画仅作用于独立进度填充层或通知 opacity，避免采样错位和液面抖动。
- 数字使用等宽数字 `font-variant-numeric: tabular-nums` 并预留计数宽度。状态槽尺寸稳定，长文本截断/详情展开；不动画 height/width/margin/padding，不用数字滚轮、逐字动画或整卡缩放。
- 确定进度的填充层以左端为原点，用 `scaleX(0…1)` 在收到新值时 linear 过渡 150ms，不越过后端数值、弹回或假装连续推进。`prefers-reduced-motion` 下直接切换填充值、保留轻微 opacity 渐变；未知进度用文字反馈。运行态不依赖会自行结束的 toast 倒计时。
- 顶栏/普通卡片采用对应玻璃层级；通知浮在复杂背景上时使用菜单级可读磨砂底，必要时降低透明度，保证文字对比度；不在信息密集区靠加重模糊补救对比度。界面固定暗色。

## 5. 可访问性与验收

- 已知进度使用带阶段名称的 `role="progressbar"` 和准确 `aria-valuemin/max/now`；未知总量省略 now，以 `aria-valuetext` 描述已完成数量。阶段状态有文字，不能只靠颜色。
- 结果通知用 `role="status"` / `aria-live="polite"`，紧急且阻断操作的错误才使用 alert；阶段转换和最终结果才播报，计数更新节流，不每次轮询朗读所有数据。撤销与重试可键盘操作，焦点清楚且不会因自动移除而丢失；焦点在通知内时不自动移除。
- 验证慢网请求中立即反馈、总量从未知到已知、上游重复记录、分页/AI 部分失败、缓存命中、无 AI、无适用项、断线重连、重载及容器重启的状态真实性。
- 以可控计时验证 3 秒完整可见后才淡出、归档默认 8 秒、隐藏/悬停/焦点暂停、通知队列和重试不重复，以及任务运行超过通知时长仍保留入口。
- Chromium 与 Safari、手机窄屏及软键盘、长文本、多任务与连续收藏操作下检查可读性、点击命中、通知遮挡和布局位移；正常与减少动画模式均检查。放慢动画逐帧确认无波纹、边缘漂移、跳动或尺寸反馈循环。
- 验收状态摘要仍满足 8 KiB、单次状态轮询和隐藏页面停止的约束。此文只定义待验证行为，不代表上述流程已经实现或测试通过。

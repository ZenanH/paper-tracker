# 本地性能验证（2026-10-29）

复现：Node 24.22.1，`pnpm benchmark 100000` 或 `pnpm benchmark 1000000`。
脚本在系统临时目录创建独立 SQLite 库，结束自动删除，结果写入本目录。
不读取实例密钥、不访问 Crossref/AI、不修改用户数据库。

## 覆盖与方法

- 1,000 本期刊，分别 100,000 / 1,000,000 篇论文、对应状态与列表投影，同等数量的历史翻译任务。
- 列表固定 20 篇，检查数量和 64 KiB 预算；状态查询、首页、游标、跳转中页/末页、任务领取和 fencing 提交、整刊归档后计数。
- 普通查询 40 次；中/末页各 10 次；首次缓存未命中各 1 次，单样本不代表统计性 P95。
- 120 个模拟请求，3 个槽；第一个 1,000ms，其余各 10ms。旧的每三请求整批等待与新持续补位分别测量。新池每项经过真实 SQLite 领取/提交，验证无重复、全部完成、峰值并发 3。
- `tests/pool.test.ts` 另测慢请求期间持续补位、取消后全部槽退出，以及异常时先等待清理再返回；`optimization.test.ts` 覆盖分页及归档后的缓存失效。

## 最终结果

时间单位 ms。P95 是本机样本，不是线上承诺。

| 项目 | 10 万篇 | 100 万篇 |
| --- | ---: | ---: |
| 首次列表（计数缓存未命中，单次） | 8.59 | 69.43 |
| 首页 P95（缓存命中） | 0.35 | 0.44 |
| 中页 P95（缓存命中） | 0.70 | 1.23 |
| 末页 P95（缓存命中） | 0.46 | 1.57 |
| 游标翻页 P95 | 0.59 | 0.37 |
| 首次状态（任务计数缓存未命中，单次） | 11.45 | 98.52 |
| 状态 P95（缓存命中） | 0.10 | 0.10 |
| 领取/提交 P95 | 0.25 | 0.48 |
| 整刊归档 | 6.36（100 篇） | 131.73（1,000 篇） |
| 模拟旧批次屏障总耗时 | 1,429.67 | 1,423.42 |
| 模拟新池总耗时 | 1,006.18 | 1,001.83 |

慢请求结束前，其余 119 项均已完成；模拟总耗时减少约 30%。百万篇进程 RSS 约 121 MiB，数据库约 629 MiB（合成标题较短，不能用于推断真实磁盘容量）。示例页 7,988 字节，gzip 829 字节；这是序列化样本，不是实际 HTTP/慢网吞吐实测。

`baseline-100000.json` 保留优化前的深页遍历结果（末页 P95 861ms）；`intermediate-1000000.json` 保留任务领取索引及缓存优化前的百万篇结果。最终原始结果见两个 `benchmark-*.json`。

## 实现

- 每个空闲槽独立领取小批任务，完成即补位；抓取最多 3 个槽但受实时 Crossref 容量限制，单批翻译最多 10 条。
- AI 过滤/翻译共享进程内请求闸门，上限 3；429 的 Retry-After 冷却期间停止发起新请求，不取消已经在途的请求。网页连接测试处于另一进程，不计入 worker 的进程内上限。
- Stop 通过持久任务 fencing 和 AbortSignal 传播；每个批次独立取消，不因其他批次完成而误取消。
- 领取任务使用仅含 queued/retry/running 的部分索引，避免历史成功任务拖慢领取。
- 跨刊跳页先定位期刊，再在刊内 seek；计数按 Store、content_version 和入库序号上界缓存，仅保留一份，不缓存全量标题。列表变更后首次请求重建计数。
- 任务统计按 progress_version 缓存，版本变化即重新计算；Scope、心跳和可见总数仍每次读取。

## 边界

测试覆盖本机单实例数据库与模拟上游延迟，不是 HTTP 并发连接、浏览器渲染、真实 Tailscale 丢包或真实上游限流的压力结果。缓存持续失效时，百万篇列表/状态仍需约 69/99ms 首次计算；归档大量论文仍为同步事务。真实服务仍受配额、延迟及网络质量影响，不能通过无限增加并发解决。

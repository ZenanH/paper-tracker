# 数据存储与慢网络传输决策

状态：已确定的实现契约，尚未实现或做应用性能验收。适用于个人 Docker 实例、关注期刊较多、通过 Tailscale 访问的场景。业务语义以根目录 `AGENTS.md` 为准。

## 1. 决策总表

| 层次 | 固定技术路线 | 分片/压缩策略 |
| --- | --- | --- |
| 内置期刊目录 | 构建时从锁定 CSV 生成只读 `catalog.sqlite`，包含 ISSN、名称索引 | 不向客户端下发整库；索引查询后返回候选 |
| 在线用户数据 | 宿主机本地 `paper-tracker.sqlite`，SQLite WAL，关系表与索引 | 首版单库，不按期刊/月拆数据库，不整库 gzip |
| 单篇详情 | 按需组合已入库的完整标题、期刊资料、日期及 AI 结果 | 无摘要、正文表或压缩 BLOB；不另行补抓大段文本 |
| 浏览器列表 | UTF-8 JSON，按期刊/收藏条件 keyset 分页 | 默认 50 条、最多 100 条；单页未压缩 UTF-8 JSON 至多 64 KiB；符合协商时 HTTP gzip |
| 更新通知 | 小型版本状态接口，客户端按变化失效当前页 | 不下发整库或全量 change log；ETag/304 减少重复正文 |
| 抓取任务 | 按 ISSN、出版日期窗口和 cursor 分页 | 大窗口按日期分片，缩小返回字段，页面提交 checkpoint |
| 备份 | SQLite 一致性快照 + `manifest.json` + 独立 gzip 文件块 | 快照按未压缩 16 MiB 分块，各块 gzip level 6、SHA-256，可只续传缺失块 |

这里有三种不同的“分片”：抓取的日期任务分片、网页的结果分页、备份的文件分块。它们不改变在线用户数据库的逻辑完整性。

## 2. 网络拓扑

```text
浏览器 ── Tailscale / HTTPS ── web ── 本机 SQLite
                                 ↑       ↑
                                 └── worker
                                      ├── Crossref 公共 API
                                      └── 用户自己配置的 AI API
```

- 论文查询、过滤、翻译在 Docker 主机上进行。浏览器接收已处理的列表，不承担从 Crossref 下载三个月元数据或批量调用 AI 的工作。
- web、worker 和数据库放在同一 Docker 主机。不能为了远程访问，把在线 SQLite/WAL 目录放进经 Tailscale 挂载的 SMB/NFS 网络共享。
- 默认不启用 Tailscale exit node 或应用层转发让外部抓取绕经浏览器；主机的实际出口仍由部署者网络配置决定。
- 如果用户的 AI 服务本身位于 tailnet，按明确配置的允许 origin 访问；服务端到该 AI 的延迟独立监测。前端的精简传输不能保证远端模型处理也快。
- Tailscale 可能直连、peer relay 或 DERP 中继。排障用 `tailscale status` / `tailscale ping` 核实，不宣称加入 tailnet 自动获得高速直连。参考 [官方连接类型说明](https://tailscale.com/docs/reference/connection-types)。

## 3. 保存格式、字段与索引

### 3.1 用户数据库

- 唯一的业务事实来源是 `paper-tracker-data/data/paper-tracker.sqlite`；数据库文件在宿主机本地盘，整个目录读写挂载到 `/app/data`。
- 用普通 SQLite 表保存期刊、关注、DOI、标题、翻译、用户状态、AI 结果和任务；UTF-8 TEXT、INTEGER、BLOB，禁止用一个不断扩大的 JSON 数组或每篇一个文件保存主数据。
- 内部主键和入库序号为 SQLite 整数；API 中 ID/序号序列化为十进制字符串，避免 JavaScript 整数精度问题。时间点为 UTC epoch 毫秒整数，出版日期另存 ISO 日历文本和精度字段。
- `paper` 保留 DOI/外部 ID、journalId、原题、出版日期/排序键和原文链接。`paper_state` 保留归档、收藏与人工覆盖。`paper_ai_result` 保留当前译题、分类及其配置/输入版本。用户状态和元数据更新仍然严格分离。
- 原题、中文题、DOI、日期、归档/收藏标志不压缩，它们用于列表、排序、索引和搜索。译题只保存一次，不能每次刷新重译。
- 不请求或保存论文摘要，不为分类或详情补抓摘要、作者长列表、参考文献、全文或原始上游大响应。上游意外附带的 `abstract` 在适配器边界丢弃，不进入业务对象、缓存、日志、导出与备份。
- 首版不建立 `paper_detail` 表，也不做字段级 gzip BLOB；单篇详情从已保存的论文、期刊资料和 AI 结果组合，完整原题按需读取。HTTP 响应与备份仍按各自规则压缩。
- 用户 key 仍加密保存在外挂数据库，加密密钥在独立外挂 secret 文件；压缩不是加密，不用 gzip 处理替代凭据加密。

### 3.2 列表投影与计数

- 为大规模收件箱维护可重建的 `paper_listing` 投影，保存 paperId、journalId、稳定出版排序键、inboxVisible、favorite 标志及版本；事实仍来自原始元数据和用户状态。
- 建立按期刊和排序键覆盖的可见项索引，以及收藏的全局排序索引，例如 `WHERE inbox_visible = 1` / `WHERE favorited = 1` 的部分索引。不能在每次请求中先扫描该刊全部已归档论文再筛出 50 条。
- 维护 `journal_stats` 的可见/收藏计数与版本；元数据、归档、收藏、AI 判定和对应投影/计数更新在短事务内一致提交。整刊操作分清事务快照范围，不把数万 ID 发给浏览器处理。
- Prompt/过滤开关使大量结果需要重算时，分批更新投影与计数，展示处理中；不能把尚未计算的数量当作准确的零。投影允许从事实表重建，不可成为唯一 tombstone。
- 查询必须检查 `EXPLAIN QUERY PLAN`；优化查询与索引先于物理拆库。单主机、单 worker 下，不以“期刊多”直接引入逐刊/逐月数据库分片。未来要多机多 writer，需独立评估 PostgreSQL 迁移。

### 3.3 内置只读目录

- 两份原始 CSV 留在源码仓库作为可复现来源；构建脚本生成独立 `/app/catalog/catalog.sqlite`，运行时只读连接，不使用 WAL 或写入用户数据。
- 目录内包含刊号唯一/关联索引、规范名称与别名的搜索索引；查询只读服务端数据库，不把数万期刊 JSON 嵌入 JS、HTML 或 RSC 响应。
- 搜索一次最多返回 20 个候选，查询防抖约 300ms、取消过时请求，支持回车立即搜索。短词也要有明确索引/限制策略，不承诺对任意一字模糊检索整库。

## 4. 浏览器协议与响应预算

### 4.1 首屏与按需加载

- 首屏只加载界面壳、最多 20 个期刊组头及当前一个期刊的第一批论文。其他期刊折叠时不请求其论文；组头也分页，不一次渲染全部关注期刊。
- 列表响应只含 `id, journalId, titleOriginal, titleZh, published, datePrecision, favorite, archived, aiStatus` 等必要字段。所属期刊资料按页去重，以字典引用；完整标题、期刊资料及分类理由在详情接口从已有记录按需组合，详情无摘要。
- 论文列表项允许标题预览截断，单项必须明确 `titleTruncated`，全文标题在详情中可取；不能为满足字节预算静默丢掉论文或改写事实原题。
- 初次 HTML/RSC 不复制一份已经在 JSON 页中返回的完整列表；首次数据传输选一个来源。按需加载设置、详情、归档管理等非首屏代码。
- 不自动预取所有路由/期刊/详情，不使用外部字体、装饰图片或 CDN 脚本作为首屏依赖。滚动到末尾或点击“加载更多”才取下一页；虚拟列表只优化渲染，不能代替网络分页。

### 4.2 Keyset 分页

建议契约：

```text
GET /api/journals?limit=20&cursor=...
GET /api/papers?journalId=...&limit=50&cursor=...
GET /api/favorites?limit=50&cursor=...
GET /api/papers/{id}
GET /api/status?scope=...
POST /api/journals/{id}/archive
```

- `cursor` 为有版本、签名、长度上限的 opaque token，包含查询范围 hash、最后 `(publishedSort, id)`、首次请求的入库序号上界和分页模式；使用 tuple keyset 条件，禁止深层 `OFFSET`。
- 插入新论文不改变当前浏览页的上界；提示有新内容时由用户刷新首屏。出版日期更正/归档/过滤属于在线变化，不宣称跨多次请求具有数据库快照隔离；客户端按 ID 去重，显式刷新可恢复最新视图。
- 论文页默认 50 条、上限 100 条，同时按序列化后的 UTF-8 字节限制整个 JSON 正文不超过 64 KiB。达到字节上限就减少条数，`nextCursor` 必须指向实际返回的最后一条，不跳过未返回项。极长标题先生成有限预览，使单条也可返回。
- 返回 `items, nextCursor, hasMore, viewVersion, asOfSeq`。不对每次翻页执行全局 `COUNT(*)`；需要的期刊数量从维护好的 stats 读取。
- 收藏与归档动作只发送目标 ID/期刊 ID和操作 token，整刊归档由服务端确定入库快照上界；响应只回确认、变化数量和相关版本。提供可撤销操作 ID，不能把所有已归档论文随响应返回。
- 写操作带幂等 token 并在数据库持久去重，网络断开后重试不会重复 toggle 或把收藏反向取消。设置/状态修改使用“设置为目标值”，不使用不可安全重放的裸 toggle。

### 4.3 压缩、缓存和轮询

- JSON 为 UTF-8，动态响应默认采用标准 HTTP gzip 协商，应用压缩 helper 使用 level 4、正文达到 1 KiB 再压缩；同时保留客户端只接受 identity 的正确行为。不能假设压缩能把任意大响应变成可接受的列表。
- 保持 Next.js 页面/静态资源压缩开启；验证 Route Handler 实际 `Content-Encoding`。若框架未压缩 JSON，由上述 helper 负责；已有 `Content-Encoding` 不再二次压缩。
- 用户有支持 Brotli 的反向代理时可交给代理优先 `br`、gzip 兜底，应用与代理仅有一层压缩。首版不把额外代理容器当成必需，也不要求浏览器下载 `.gz` 后自行解压。
- 设置 `Vary: Accept-Encoding`；表示压缩前相同内容的校验器使用弱 ETag，或使用编码专属强 ETag。禁止不同字节表示错误共用强 ETag。
- 已登录的列表/详情可使用 `Cache-Control: private, no-cache` + ETag，先验会话再返回 304，客户端保留有限页面缓存并在登出/换实例时清理。会话身份信息、登录、设置及任何密钥相关响应使用 `no-store`，不回显可利用的明文 secret。
- ETag 覆盖实例/会话身份范围、查询与游标、数据/视图版本；版本按内容真实变化才增加。不要每轮“抓到了重复论文”就使所有列表缓存失效。
- `/api/status` 一次返回实例及当前屏幕最多 20 个期刊的版本/小计数，原始 JSON 上限 8 KiB。只在这些版本变化后重新加载相关已显示页，不向每本期刊发一个轮询请求，也不构造全量逐篇 change log。
- 状态正文同时包含当前任务的有界四阶段摘要：阶段状态、已完成/已知总量（未知为 null）、失败/等待数、进度版本、最近确认时间及必要的重试时间。不得附带逐篇处理记录或全部任务日志；超出屏幕范围的任务只给汇总数量，展开详情才分页查询。8 KiB 预算包含这些字段，详细口径见 `../design/progress-and-feedback.md`。
- 页面可见且后台有任务时，单个状态轮询每 15 秒一次；空闲时每 60 秒，标签页隐藏时停止，失败退避到最多 120 秒。请求不重叠，断网时停止并保留已加载列表，恢复联网后先校验版本。
- 轮询未变化返回 304；任务有变化也只返回计数/版本。首版不依赖 WebSocket、频繁 SSE 心跳或完整离线数据库同步。
- 用户操作立即在本地显示“正在提交/正在获取”状态，再由原请求响应校正；入队响应包含任务 ID 和初始摘要，避免等待下一轮轮询才反馈。归档/收藏通知依照服务端幂等操作 ID 去重，不因刷新或自动重试重复弹出成功通知。状态计数变化只更新进度区，不因此重新拉取未变化的论文列表。
- 浏览器应用内页面缓存最多 10 页或 1 MiB 解码 JSON（先达到者为准），使用 LRU 淘汰；它是减少重复传输的可丢弃副本，不能代替外挂数据库。初版不持久缓存全部论文或引入 Service Worker 离线同步，缓存不会包含 API key。
- 带 hash 的构建静态资源使用长期 immutable 缓存；页面壳和鉴权路由不共享缓存，不能为了省流量把私有页面缓存到公共代理。

## 5. 源站抓取与 AI 的传输控制

- 仍按用户规定的三个月/部署月下界回扫，不擅自改为只抓最近一天。每次元数据内容 hash 未变化时，不重写内容/触发翻译/递增视图版本。
- Crossref 支持时用 `select` 请求本轮确需字段，例如 DOI、title、ISSN、各出版日期、URL、type；完整作者、摘要和参考文献不加入每日全量回扫。实际字段支持需用适配器测试确认。
- 必要的期刊归属由当前已确认的 ISSN 和来源记录共同确定，不能因省略 `container-title` 把不匹配期刊错误合并。轻量列表有足够身份与日期信息才入库。
- 默认每页 200 条，按返回解压后的字节数和请求延迟监测高产期刊；超过 2 MiB 时后续页降到 100，再到 50。降 page size 导致 cursor 不兼容时重启当前日期分片并幂等去重。单条异常大记录隔离，不无限扩大内存。
- 接受源站支持的 HTTP 压缩，设定解压后响应体上限，例如 8 MiB，超出后缩小页/日期范围再试；不能直接全量 `response.json()` 读入无限响应。
- 日期分片以月为起点，高产/超时则二分到周或日；同刊不同刊号依 DOI 合并，cursor 失效只重做当前分片。任务 checkpoint 存允许窗口、已完成分片与来源参数。
- 过滤仅使用原题；标题信息不足时保留并标记不确定，不额外请求摘要、详情或全文来辅助分类。
- AI 只处理新增/标题或相关规则变化的论文。默认每批最多 10 篇且受 token/字节预算约束；每篇输入仅 paperId 与原题，翻译仅处理保留项原题，不把期刊目录、用户状态、历史论文或摘要发给模型。
- 分类与翻译仍逻辑分步，保留分类结果后再翻译；各自缓存。用户自己 API 的 token/限流与 Tailscale 页面吞吐分开显示。
- 不缓存整个 Crossref HTTP 页作为永久业务数据。保留必要字段、标题/元数据 hash、来源/获取时间、错误类型与简短错误描述即可；诊断日志轮转且不记录论文正文或密钥。仅标题变化使对应标题处理缓存失效，日期等其他元数据变化不应触发重译。

## 6. 备份文件格式与断点传输

- 在线 SQLite 保持可读写，不进行原地分片、压缩或远程文件同步。使用 SQLite Backup API 得到同一时点的一致性快照，再压缩传输；不能复制仍在写入的主库并忽略 WAL。
- 快照输出到 `paper-tracker-data/data/backups/<snapshot-id>/`，先写 `.partial`，全部校验后写完成标志并原子发布，任务失败不生成假完整备份。
- 将快照原始字节流每 **16 MiB** 切一块，每块独立 gzip level 6，命名 `part-000001.bin.gz`；最后一块可更小。不能先 gzip 整库再任意切开压缩流。
- 分块、hash、压缩与恢复采用流式/有界缓冲逐块处理，默认一次处理一块，不把全库读进内存。备份前检查剩余磁盘，预算同时覆盖在线库/WAL、临时完整快照和已压缩输出；空间不足明确失败，不依赖未经实测的压缩比。
- `manifest.json` 包含 formatVersion、snapshotId、创建时间、应用/schema/SQLite 版本、原库大小和 SHA-256，以及每块的序号、未压缩长度/偏移、压缩长度、原始/压缩 SHA-256。清单本身不包含密钥或明文 API 配置。
- 下载中断后使用同一 snapshotId 继续，只补缺失/损坏块；支持的传输工具可在单个块文件上续传。恢复时逐块校验、解压并按顺序拼接，核验整库 hash 和 `PRAGMA integrity_check`，再切换到恢复目录。
- 这只保证**同一快照**的分块续传；不同日期快照不承诺块复用、增量备份或内容去重。不要直接 rsync 正在使用的 SQLite/WAL 目录。
- 默认备份通过宿主机脚本生成，管理员经 SSH/SFTP/rsync 等授权文件传输取走；不新开未鉴权数据库下载接口。gzip 仅压缩，备份文件仍受宿主机权限保护；敏感环境按部署者备份策略加密。
- `secrets/` 独立备份，不写入普通数据分块或清单；完整恢复需匹配原来的加密密钥。在线备份时不得更换数据库使用的加密 key；将来的密钥轮换须与备份事务协同设计。
- 备份是用户主动/配置日程触发的后台任务，不在普通网页刷新时传输，也不启动后自动把整库同步到浏览器。清理旧备份依据显式保留策略，不能删除在线用户数据。

## 7. 容量与慢网络验收

以下数字是开发预算/验收目标，不是已测成绩或容量承诺：

| 项目 | 目标与硬边界 |
| --- | --- |
| 常规论文页 | 默认 50 条，完整 JSON ≤64 KiB 未压缩；典型样本 gzip 后目标 ≤20 KiB |
| 期刊候选/组头 | 候选最多 20 个；组头默认 20 个分页，不携带各刊论文 |
| 状态轮询 | ≤8 KiB 未压缩；未变化返回 304，无正文 |
| 单篇详情 | 原始 JSON ≤64 KiB，仅已有标题/期刊/日期/AI 结果；字段截断明确标注 |
| 首次打开 | 壳、脚本、样式和首批业务数据合计 gzip 传输目标 ≤250 KiB；无外部字体/装饰图 |
| 后续翻页 | 只增加该页正文，不重传整个组/全部期刊/全部论文 |
| 数据规模基线 | 1,000 本关注期刊、1,000,000 条合成论文，含大量归档与收藏，验证索引、分页、计数和任务内存 |
| 网络基线 | 下行 256 kbit/s、RTT 300ms，另测更差网络/断线/恢复；不声称跨所有链路稳定秒开 |

- 20 KiB 仅在 256 kbit/s 下传输约 0.64 秒，250 KiB 约 8 秒，均未计 RTT、TLS、协议开销和服务端时间；因此首屏预算必须约束 JS/CSS，而不只压缩论文 JSON。
- 验收记录首屏/后续页线上实际字节、HTTP 编码、请求数量、查询计划、查询 p50/p95、worker 峰值内存和 SQLite/WAL/备份大小。报告测试硬件、网络整形方法及真实/合成数据来源。
- 在网络面板确认隐藏期刊不触发 N+1 请求，未变化轮询没有完整列表正文，整刊归档请求/响应大小不随论文数量线性增长。
- 在百万行基线上验证深分页不出现 OFFSET 扫描或全表物化，长期运行 worker 不把所有论文/目录加载到 JS 内存。若性能目标不达标，应修索引/投影或明确调整架构，再交付。
- 容量按实际 `必要元数据 + AI 结果/用户状态 + 索引 + WAL + 备份/临时快照` 统计；条数不能直接换算成固定磁盘大小。基线不是上限或无限容量保证；达到千万级论文/多机并发需求时，以测量结果决定是否单独迁移数据库，不能无评估复制运行中的 SQLite 文件做分片。
- 验证请求字段不含 abstract、适配器丢弃附带摘要、数据库/缓存/日志/导出不存摘要、AI 输入无摘要；标题不确定时保留，不能触发摘要补抓。
- 构建与压缩预算需要应用实现后测试；当前仓库只有来源快照与规范，不把此设计描述为已经跑通的系统。
